# 15 — 9. QC Nghiệm Thu (AV Grade)

Menu: `qc` → `QCPage.tsx`, xác nhận qua `App.tsx` (`case 'qc'`).

## Frontend gọi gì

```ts
qcApi.completeQc(jobId, passed, comments)   // POST /DepotJobs/{id}/qc-complete
shippingApi.syncJob(jobId, carrierCode, 'QC_PASSED')  // trong ShippingLineDispatchModal — xem 16-shipping-api.md
```

## Đối chiếu backend

- `POST /DepotJobs/{id}/qc-complete` → `DepotJobsController.CompleteQc([FromBody] QcInspectionRequest)`:
  route có `{id}` nhưng **action không nhận tham số `id` từ route** — toàn bộ định danh job lấy từ
  `qcReq.JobId` trong body (`Guid.TryParse(qcReq.JobId, ...)`). Vì frontend luôn gửi cùng 1 giá trị
  `record.containerId` cho cả URL lẫn field `jobId` trong body, kết quả vẫn đúng — nhưng đoạn `{id}`
  trên route là dư thừa/gây hiểu nhầm khi đọc code (tưởng route id mới là nguồn xác định job). Không
  sửa vì không gây lỗi thực tế, chỉ ghi chú để tránh nhầm lẫn khi có người sau sửa lại route.
- `CompleteQcInspectionAsync`: yêu cầu `RepairOrder` tồn tại và `Job.Status == "QC_PENDING"` (đúng nối
  tiếp màn 14) → Pass: `Status = "READY_FOR_OUT"`, `RepairOrder.QcStatus = "PASSED"`; Fail:
  `Status = "REPAIRING"` (quay lại sửa), `QcStatus = "FAILED"`. ✅

## Quan sát (nit nhỏ, không sửa)

- `App.tsx` optimistic update set `status: 'READY_FOR_USE'` khi Pass, nhưng backend thực set
  `"READY_FOR_OUT"` — cùng kiểu lệch nhãn tạm thời đã ghi nhận ở màn 13/14, không phải lỗi tích hợp.
